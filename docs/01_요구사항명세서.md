# 01. 요구사항 명세서 (SRS)

> 프로젝트: 멀티팩터 기반 종목 선정과 투자 성향별 포트폴리오 (데이터처리프로그래밍 2조)
> 버전: 3.0 (2026-11-11) · 대상 독자: 백엔드 개발자 (Spring 팀, Python 팀)
> 근거: [기능정의서 v3](../기능정의서.md), [기획_결정기록](../기획_결정기록.md) · 관련: [02 아키텍처](02_시스템아키텍처설계서.md), [03 도메인/API/DB](03_도메인_API_DB설계서.md)

이 문서는 **무엇을** 만들지 정한다. **어떻게**는 02·03 문서에 있다. 요구사항마다 ID와 **수용 기준**(통과하면 끝)이 있으니 테스트로 그대로 옮기면 된다.

## 1. 범위

### 1.1 만드는 것
- 로그인한 사용자가 온보딩(투자 금액·성향 진단·추가 문항·보유 종목)을 마치면, **KOSPI 주식 + 채권 + 현금** 포트폴리오를 근거와 함께 추천한다.
- 사용자는 결과를 고친 뒤 **매수 완료** 처리하고, 이후 포트폴리오를 추적하며 **리밸런싱 알림**을 받는다.
- 전략 검증용 **백테스트**(실험 A~D)를 돌린다.
- 이를 위해 서비스 2개를 만든다 [11-1].
  - **service (Spring Boot, 모듈러 모놀리스)**: 회원, 설문·프로필, 추천 버전·문구, 포트폴리오, 알림 상태, Thymeleaf 화면
  - **quant-engine (Python)**: 시장 데이터 적재·갱신 배치, 모든 계산(지표·점수·배분·평가·알림 조건·백테스트)
- 요구사항 ID 앞의 **[S]**·**[P]**는 담당 서비스다. 표시가 없으면 [S]가 사용자에게 제공하고 [P]가 계산한다.

### 1.2 만들지 않는 것
- 실제 주문·매매, 증권사 연동
- 장중 실시간 시세 (향후 계획)
- KOSPI 외 자산(예금·펀드·코스닥·해외) 보유 입력 (향후 계획)
- **서비스 안의 AI 기능** (프로젝트 원칙)
- 비밀번호 찾기, 이메일 인증, 권한 등급

### 1.3 용어

| 용어 | 정의 |
|---|---|
| 기준일 | 계산에 쓰는 가격 날짜. **항상 DB의 최신 영업일**(사용자가 고르지 않음) |
| 영업일 | `exchange_calendars` XKRX 세션 |
| 적용일 | 재무를 쓰기 시작하는 날 = 회계연도 + 1년의 4월 1일 |
| 기본 등급 | 7문항 총점으로 정한 STABLE / NEUTRAL / AGGRESSIVE |
| 프로필 | 기본 등급 + 설문에서 나온 세부 설정값 묶음. Spring이 계산해(03 §6.1) 엔진에 `ProfileSettings`로 보냄(03 §1.2) |
| 데이터 버전 | 엔진의 마지막 성공 배치 ID. 모든 계산 응답에 포함 |
| 유니버스 | 공통 필터(F4)를 통과한 추천 후보 |
| 업종 그룹 | 업종 중립 순위를 매기는 단위 (후보 10개 미만 업종은 묶음) |
| 안전자산 | 채권 + 현금 |
| 채권 지수 | 국고채 3년 금리로 계산한 지수 (03 §1.3) |
| 목표 비중 | 매수 완료 시점의 계획 비중. 리밸런싱 기준 |
| 비율 | 모두 소수 (0.123 = 12.3%) |

**골든 프로필** — Q 모두 3번(14점, NEUTRAL), Q7 3번, A2 "10% 이하", A3 "없다", A4 "50~80%", A5 "상관없음", A6 ["배당"], A7 []:
- 손실 한도 -0.10, 최소 현금 0.15, 주식 상한 0.55, 종목 수 15
- 가중치 (가치·수익성·추세·안정성·배당) = (0.30, 0.30, 0.25, 0.15, 0.10)/1.10 = (0.2727, 0.2727, 0.2273, 0.1364, 0.0909)
- 필터: 변동성 상위 10% 제외 + 과열 제외 (Q2 3번이므로 안정형 필터 아님)
- 한도 종목 0.20 / 업종 0.40, 기본 방식 INVERSE_VOL
